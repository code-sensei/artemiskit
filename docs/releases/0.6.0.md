# 0.6.0 release candidate

Status on 25 September 2026: **implemented, versioned and locally validated; npm publication blocked**.
The configured local publishing credential returns HTTP 401 from npm authentication and the package
publish-access endpoint. No 0.6.0 npm publication, milestone tag or GitHub release is claimed.
The next milestone starts after this release's registry-install and remote-tag gates pass.

## Included behavior

- Strict version 1 `agent_workflow` scenarios, twelve simulated tool primitives, declared authority
  and bounded metadata evidence, and a provider-neutral single-turn target.
- CLI authoring, tools list/describe and offline scenario validation; matching public core/SDK exports.
- Structured OpenAI tool-call transcript preservation, with OpenAI and Ling loopback transport proofs.
- Node-compatible library bundles and TypeScript NodeNext declarations. The CLI and Docker MCP server
  keep Bun entry points. Runtime qualification used Node 24.18.0 and Bun 1.3.10 on macOS arm64.

Full loops, cumulative budgets, disposable sandbox execution, independent outcome scoring, durable
resume and workflow reports are later milestones in the [release plan](0.6.x-release-plan.md).
Existing prompt scenarios remain supported. No optional experimental harness is promoted to a
production integration, and no external model, Docker, Windows or Linux runtime is newly qualified.

Fresh consumer verification packs all thirteen packages, installs outside the repository, and checks
exact internal workspace dependency versions. It exercises installed CLI scaffolding/validation,
eleven library imports and SDK subpaths under Node/Bun, schema and approval/denial behavior, real
OpenAI/Ling adapters with loopback tool continuation, and TypeScript NodeNext/bundler consumers.
Other adapters are import-qualified only. TypeScript uses `skipLibCheck` for dependency internals,
with concrete public-type and expected-error assertions. No provider credentials or paid calls
are needed for these checks.

The original Bun-targeted library bundles failed Node imports. Node-targeted ESM, workspace package
externalization and generated declaration finalization resolved the independently reproduced failure.
One worker fixture initially used an HTTP cleanup order incompatible with Bun; correction passed
both runtimes and independent review.

The first integrated versioned consumer then caught a separate failure: Bun 1.3.10 retained old
workspace versions in `bun.lock` after Changesets, including after ordinary and forced lock-only
installation. Packing CLI 0.5.0 resolved its core dependency to 0.5.3 and fetched an incompatible
nested core. `bun run version` now synchronizes only workspace-version metadata after Changesets;
registry resolutions remain unchanged. A regression test verifies preservation/idempotence and
fail-closed handling of unfamiliar lock structure. The second fresh consumer passed every check,
including exact packed dependency versions. Consumer artifacts remain in machine-local temporary
directories; they contain no publishing credentials.

The [original source validation](0.6.0-validation.md) and [harness experiment](../agent-harness-experiment.md)
retain model failures and limitations: two larger local-model smoke runs timed out; all 48 selected
Qwen3B structured-tool trials failed. These do not establish live-agent quality or supported-provider
coverage. CI repair remains deferred.
