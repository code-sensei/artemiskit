## Delivered behavior

This describes what the published 0.7.0 packages contain.

`@artemiskit/core` adds the comparative experiment contract. A strict V1 manifest declares tasks,
targets, repetitions, retry policy, concurrency, seed, budgets and exclusions. `runExperiment`
expands a deterministic task × target × repetition matrix and keeps retries inside the original
coordinate. Capability gaps, exclusions, invalid measurements, infrastructure failures and
incomplete work stay visible and outside valid-outcome rates. Summaries carry
`uncertainty.method: none`. Live runs need an explicit authorization with request, token and cost
budgets, and results record the authorization, consumption, stop reason and runtime exclusions.

The built-in `scenario_evaluation` executor runs scenario tasks through the existing runner against
configured adapter targets. It verifies each task source's SHA-256 before parsing, meters every
request and hashes the run manifest as evidence. A response cut off at its token limit is invalid
(`response_truncated`), not a task failure. Per-target generation settings (temperature, `top_p`,
`presence_penalty`, seed, output cap, `reasoning_effort`) apply to target requests only and are
recorded in run evidence.

The built-in `agent_workflow` executor runs workflow tasks through the native workflow engine
against the same targets, only in the workflow's declared `simulated` or `sandbox` environment with
network denied. It verifies the workflow's SHA-256 before parsing, parses without `${VAR}`
expansion, and saves the metadata-only workflow record (no model text or fixture content) as
digest-named evidence. Every workflow model request carries the target's temperature, `top_p`,
`presence_penalty` and output cap and the coordinate's per-repetition seed; the target's client
sends `reasoning_effort`. The record's `configuration.generation` lists each value sent, so a seeded
experiment with Qwen-style sampling measures workflow tasks instead of recording them invalid.
`top_k` and `min_p` are refused for both task kinds because no request transport sends them.
Policy denials and exhausting a workflow's own budgets are `policy_failed`. Workflows with semantic
outcomes are refused, because experiment runs configure no independent judge.

Concurrency may be declared from 1 to 8 (1 is serial). Live runs above 1 need an approval naming the
level. See release plan decision 4 for the admission, micro-unit cost and overrun-bound guarantees.
Local open-weight targets can declare `cost_basis: not_applicable` on loopback endpoints only. Such
targets need token usage and are never assigned a cost.

`@artemiskit/reports` validates a saved V1 result and renders technical, executive and
comprehensive views in HTML and Markdown offline. It makes no ranking or winner claim.
`akit experiment validate | run | report` and the matching SDK functions share one engine. Runs use
fixture clients by default; live runs need `--approve`, `--approved-by` and `--reason`.
`@artemiskit/adapter-openai` adds opt-in `reasoning_effort` and `presence_penalty`, and always sends
`max_tokens` to loopback endpoints.

### Local benchmark qualification

Release gate step 5 is recorded in [0.7.0-local-qualification.md](0.7.0-local-qualification.md)
([JSON](0.7.0-local-qualification.json)), status **recorded, not reviewed**. Three experiments
(`ng-egov-services`, `aml-transaction-review`, `soc-alert-triage`) ran live with `akit experiment
run` against two open-weight models, `qwen3.5:4b` and `qwen3.5:9b` (Q4_K_M) by the Qwen Team,
Alibaba Cloud (Apache-2.0). Both ran locally via Ollama 0.33.3 through its OpenAI-compatible
endpoint with the ArtemisKit `openai` provider. That's a compatibility path, not native Ollama
support.

- **Protocol.** Thinking off (`reasoning_effort: none`), temperature 0.7, top_p 0.8,
  presence_penalty 1.5, 4,096-token output cap, three seeded repetitions per task and target,
  concurrency 1. Retries on infrastructure failure only; none was needed.
- **Totals.** 924 coordinates, 3,402 requests and 6,705,364 tokens. No budget stop, no timeout and
  no infrastructure failure.
- **Invalid and truncated attempts.** One soc-alert-triage coordinate (qwen3.5:9b, repetition 2)
  hit the output cap and is `invalid` / `response_truncated`, outside the valid-outcome rates. That
  run exited 5 (valid-measurement coverage incomplete), as intended. The other two exited 0.
- **No cost.** Both targets declare `cost_basis: not_applicable` on a loopback endpoint. Tokens were
  metered and no cost was assigned; no paid API was called.
- **Draft packs.** The three packs are unreviewed drafts with synthetic data. The runs qualify the
  experiment contract, not the models, and no result ranks one model above the other.
- **AML is provisional.** The AML run was scored with a pack defect (optional keys rejected
  `null`), fixed in `259b2b3`. A clean re-run (`think-off-v2`) replaces it. The thinking-on runs
  aren't covered.
- **Pre-release build.** The runs used the CLI at `32b7532`; the scenario path wasn't re-run on the
  release candidate, and these packs don't exercise `agent_workflow` tasks (the fixture suites and
  packed consumers do).

## Boundaries

0.7.0 doesn't include operator cancellation or experiment-to-experiment comparison (0.7.1),
capability, workflow-kind, latency or per-group cost aggregates (0.7.2), or the complete live
approval envelope and paid-provider qualification (0.7.3). `assessExperimentCompatibility()` is
exported, but no comparison calls it yet. Qualification is limited to local endpoints, which is a
stated release limitation. Results never rank targets. With concurrency above 1, completion order
can differ from a serial run, and so can sampled outputs under server batching, even with fixed
seeds.
