# 0.7.1 — Long-request and reasoning-config fixes

Status on 20 November 2026: **versioned; final local gate and publication pending.** This is
a patch milestone. It ships two fixes found during the 0.7.0 local benchmark runs and adds no new
capability. The [manifest](0.7.1.json) lists the twelve package versions. Nothing is published to
npm, tagged or pushed yet.

The milestone previously planned as 0.7.1 (eligibility and completeness) is now 0.7.2, and the later
0.7.x milestones each move up by one. See [Renumbering](#renumbering).

## What's fixed

### Bun's fetch timeout no longer cuts long requests

Under Bun, `fetch` runs its own idle timer (`BUN_CONFIG_HTTP_IDLE_TIMEOUT`, about 5 minutes by
default) on top of the SDK's abort signal. A non-streaming request that received no bytes within
that window failed with "Connection error", whatever the adapter `timeout` was set to. That's the
normal shape of a request to a model that thinks for a long time before answering.

The OpenAI, Anthropic and Ling adapters now pass `timeout: false` to `fetch` under Bun, so the
configured adapter `timeout` is the only limit. Node behavior is unchanged. Tests for each adapter
assert that the fetch call receives `timeout: false` with the SDK's init and signal, and that a short
SDK timeout still aborts a request that never answers.

**How it was found.** Live 0.7.0 experiments against local thinking models (Qwen3.5 through Ollama's
OpenAI-compatible endpoint) dropped requests at 5–6 minutes. Each run then halted with
`stop_reason: usage_unreported`, because the failed request reported no token usage.

**Known remaining exposure.** These paths still use a fetch that Bun's idle timer applies to:

- `@artemiskit/adapter-trueforge` uses the default `fetch` unless the caller passes its `fetch`
  option.
- `@artemiskit/adapter-vercel-ai`, `@artemiskit/adapter-langchain` and
  `@artemiskit/adapter-deepagents` make requests through their SDKs' internal fetch.

Under Bun, a non-streaming request through these adapters that waits more than about 5 minutes for
its first byte can still fail. Streaming requests, Node, and a raised `BUN_CONFIG_HTTP_IDLE_TIMEOUT`
avoid it.

### Configured reasoning settings now reach the provider through `akit run`

The CLI config loader stripped keys it didn't declare, so `providers.openai.reasoningEffort` and
`providers.ling.thinking` were removed at load time and requests silently used the provider default.
Both are now accepted in the config file, and `reasoningEffort` in a scenario's `providerConfig`.
The scenario value takes precedence over the config file. `reasoning_effort` is sent with every
OpenAI-compatible request and recorded with its source in the run manifest. `reasoningEffort` also
accepts `xhigh`.
