## Scope

The native engine verifies declared file artifacts, final workflow state, bounded JSON schemas,
correlated successful tool calls and host policy evidence. Deterministic evaluation makes no model
calls. Optional semantic criteria require an explicitly configured independent judge with separate
identity, request/token/output/deadline limits and usage accounting. Failed deterministic prerequisites
skip judge initialization. Model self-report cannot supply missing evidence or override policy.

Version 2 records distinguish task outcomes, execution, policy, invalid/unavailable measurement,
target/judge usage and assertion coverage. `readWorkflowRecord` validates metadata consistency without
rescoring or calling providers; historical version 1 records remain unscored. Task success uses eligible
runs as its denominator, with valid failures included and unavailable/invalid tasks excluded.

CLI and SDK usage, exact status and exit semantics, JSON Schema limits, and evidence retention are
documented in [workflow outcomes](../workflow-outcomes.md). Existing prompt-response reports retain
their original contract. Durable recovery/fault injection remains 0.6.3; workflow reports remain 0.6.4.
CI repair, optional harness adoption and new hosted-model qualification are outside this milestone.
