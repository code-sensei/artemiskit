ArtemisKit 0.6.1 adds controlled multi-turn agent workflow execution through the same CLI and SDK session engine.

- Fresh simulated state or a disposable Docker filesystem, with declared tool, argument, permission and path enforcement.
- Cumulative request/action/tool/token/time budgets, explicit structured-tool preflight, cancellation and cleanup evidence.
- `akit workflow run` / `akit workflow preflight`, SDK `createWorkflowSession` / `runWorkflow`, bounded metadata records and opt-in private state export.
- OpenAI/Ling transport cancellation, retries disabled on the controlled path, and explicit unavailable usage.

Package versions are independent: core **0.6.1**, CLI/SDK **0.6.0**. The exact twelve-package map is in [the manifest](https://github.com/code-sensei/artemiskit/blob/v0.6.1/docs/releases/0.6.1.json). The unchanged MCP Docker package remains 0.1.0.

Validation: 1,482 tests / 4,207 assertions passed, all thirteen builds and typechecks passed, and lint had no errors (30 baseline warnings). Fresh Node/Bun and TypeScript consumers exercised actual installed CLI/SDK execution, loopback OpenAI/Ling continuation, and real Docker isolation/artifacts/cleanup.

Independent task verification remains unavailable until 0.6.2. Durable recovery and workflow reports remain 0.6.3 and 0.6.4. All four bounded local-model probes failed before workflow execution; their protocol failures, timeout and target error are retained rather than presented as model-quality results. Hosted-model and cross-platform qualification remain outstanding; CI repair is deferred.

See the [execution guide](https://github.com/code-sensei/artemiskit/blob/v0.6.1/docs/workflow-execution.md) for CLI/SDK examples, Docker prerequisites, budgets and exit semantics, and the [release record](https://github.com/code-sensei/artemiskit/blob/main/docs/releases/0.6.1.md) for final publication evidence.
