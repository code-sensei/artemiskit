# 0.7.0 — Local qualification runs

Machine-readable copy: [0.7.0-local-qualification.json](0.7.0-local-qualification.json).

Status: **recorded, not reviewed.** These are the thinking-off runs of the 0.7.0 local benchmark
(run `20261119-benchmark-070`), recorded on 20 November 2026. They are release gate step 5 evidence
for `akit experiment` live mode: one experiment contract run end to end against two local models.
They aren't a model evaluation. The packs are unreviewed drafts, the data is synthetic, and no
result ranks one model above the other.

The AML numbers are **provisional**. That run was scored with a pack defect (see
[findings](#qualification-findings)). A clean re-run (`think-off-v2`) is scheduled after the
thinking-on phase and replaces it. The thinking-on runs are still in progress and aren't covered here.

## What this run qualifies

Each item is 0.7.0 behavior that these runs exercised against a real local endpoint, not a fixture:

- **Live run end to end.** `akit experiment run` with `--approve --approved-by --reason` expanded
  each manifest's task × target × repetition matrix, called the models, scored every case and wrote
  a V1 `result.json` with one SHA-256-named evidence file per coordinate.
- **Loopback no-cost rule.** Both targets declare `cost_basis: not_applicable` on
  `http://127.0.0.1:11434/v1`. The run accepted them, metered tokens and assigned no cost:
  "cost not applicable (local targets only)".
- **Seeds.** `seed.strategy: increment_by_repetition` from 20261119, with `require_support: true`.
  Repetitions 1, 2 and 3 sent seeds 20261119, 20261120 and 20261121; each evidence file records the
  seed it sent.
- **Generation settings.** Per-target `reasoning_effort`, `temperature`, `top_p`,
  `presence_penalty` and `max_output_tokens` reached each request and are recorded in run evidence
  (`resolved_config`, `execution_provenance`).
- **Truncation is invalid.** One soc-alert-triage response hit the 4,096-token output cap. Its
  coordinate is `invalid` / `response_truncated`, not a task failure, and it stays outside the
  valid-outcome rates.
- **Exit codes.** ng-egov-services and aml-transaction-review exited 0 (every coordinate has a
  valid measurement). soc-alert-triage exited 5 (`coverageIncomplete`) because of that one invalid
  coordinate, and the driver carried on to the next experiment.
- **Timeouts.** `--timeout 1800000` (30 minutes) reached the adapter. The slowest case took 189.5 s
  (the truncated one); no request timed out and no attempt was `infrastructure_failed`.
- **Case-level reporting.** `akit experiment report` from current `main` regenerated all three
  views in HTML and Markdown from each saved result offline, with no provider configuration. Each
  report includes the case-level summary computed from the SHA-256-verified evidence files.

## Protocol

- Manifests: `packs/<pack>/experiment.local-think-off.yaml`, same tasks and identities as each
  pack's `experiment.yaml`, `mode: live`.
- Targets: `qwen3.5-4b-think-off` and `qwen3.5-9b-think-off`, both `reasoning_effort: none`,
  temperature 0.7, top_p 0.8, presence_penalty 1.5, `max_output_tokens` 4,096. Publisher Qwen;
  weights open, Apache-2.0; deployment local via Ollama.
- 3 seeded repetitions per task and target; concurrency 1 (serial), live concurrency ceiling 1.
  Concurrency 2 and 4 were measured beforehand and gave no consistent gain, because Ollama 0.33.3
  serves the qwen35 architecture with one request slot and the two models don't fit in memory
  together.
- Retry: `max_attempts: 2` on `infrastructure_failed` only. No retry was needed.
- Budgets: `max_requests` = cases × 2 targets × 3 repetitions × 2 attempts; `max_tokens` =
  `max_requests` × 8,096. Live stop conditions: request, token or cost budget exhausted, usage
  unreported, usage invalid, budget exceeded. No run stopped (stop reason `none`).
- Run command, one experiment after another from a driver script:

  ```bash
  bun packages/cli/bin/artemis.ts experiment run packs/<pack>/experiment.local-think-off.yaml \
    --output-dir artemis-output/experiments/20261119-benchmark-070/<pack>/think-off \
    --timeout 1800000 --max-concurrency 1 \
    --approve --approved-by project-owner --reason "Local open-weight benchmark run; no paid APIs"
  ```

- Report command (report CLI above; output in a scratch directory, not committed):

  ```bash
  bun packages/cli/bin/artemis.ts experiment report \
    artemis-output/experiments/20261119-benchmark-070/<pack>/think-off/result.json \
    --evidence-dir artemis-output/experiments/20261119-benchmark-070/<pack>/think-off/evidence \
    --output-dir <scratch>/reports/<pack>
  ```

  All three reports exited 0 and wrote technical, executive and comprehensive views in HTML and
  Markdown (6 files each).

Raw outputs (results, evidence, logs) stay in the gitignored `artemis-output/` directory and aren't
committed. The SHA-256 of each `result.json` identifies the exact file this record describes.

## Qualification findings

1. **The live contract ran end to end three times.** 924 coordinates, 3,402 requests and 6,705,364
   tokens across the three experiments, no budget stop, no retries and no infrastructure failures.
   Every coordinate has an evidence file and the report verified every SHA-256 (312 + 300 + 312).
2. **Truncation was classified, and exit 5 reported it.** The invalid coordinate is
   soc-alert-triage task `soc-21-smb-admin-share-lateral`, qwen3.5-9b, repetition 2 (seed 20261120).
   Its case `jump-host-shared-account-logs-missing` used all 4,096 completion tokens in 189.5 s. The
   model began a JSON answer, emitted a stray `</think>` mid-object and restarted the answer, 19
   times, until the cap cut it off. The run recorded `invalid` / `response_truncated`, kept the coordinate
   out of the valid rates and set `valid_measurement_coverage_complete: false`. The CLI exited 5
   with "valid-measurement coverage incomplete". That's the intended 0.7.0 behavior: a run that
   finished but has a missing measurement doesn't exit 0.
3. **soc-alert-triage failures are substantive, not format errors.** No coordinate fully passed for
   either model. Re-evaluating each sub-check offline over all 1,242 saved cases (including the 4 in
   the invalid coordinate), failures by expectation: `attack_techniques`
   608 / 1,068, `classification` 392 / 1,242, `severity` 336 / 1,242, `decision` 302 / 1,242,
   `rule_ids` 282 / 1,248, `human_approval_required` 65 / 420, `json_schema` 59 / 1,242,
   `not_contains` 8 / 72. Of the 59 schema failures, 33 list more than the 5 allowed `rule_ids`, 15
   aren't parseable JSON, 2 have a malformed technique ID, and 9 (all qwen3.5-9b) contain a stray
   `</think>` although thinking was off. That's a model output error: 8 of those are scored as
   failures, and the 9th is the truncated, invalid case above.
4. **The AML pack defect was caught and fixed.** The AML run exited 0, but its optional answer keys
   (`customer_message`, `str_narrative`) rejected `null`, so a model that wrote `"key": null`
   instead of omitting the key failed the case even when its decision was right. Commit `259b2b3`
   made optional keys accept null, `3301998` added a shared pack check that fails any pack whose
   optional key rejects null (`packs/_tools/pack-contract.ts`), and `fb762e6` documented the change. Required keys still fail on null or
   omission. All 300 AML evidence files embed the pre-fix schema, so the as-run numbers are
   internally consistent; they just measure the defective rubric.
5. **Saved results regenerate with a newer reporter.** The runs used the CLI at `32b7532`, before
   case-level summaries were added. The current-`main` CLI regenerated all reports from the saved
   results and evidence offline, with case-level counts that match the evidence files.
6. **Git provenance is captured per coordinate.** The run worktree was edited during the AML and
   soc-alert-triage runs (AML fix work, later committed outside `main` as `ac7e8e4`). The evidence
   reports `dirty: true` for those coordinates and names the commit at that moment. Task sources are
   SHA-256-verified against the manifest before parsing, the AML evidence embeds the pre-fix schema,
   and the soc-alert-triage and ng-egov-services task files are unchanged from `32b7532` to
   `f344b19`, so every scored input matches its run's declared identity.

## Limitations

- **Draft, unreviewed packs.** No domain reviewer has signed off on any pack. Results aren't claims
  about the workflow, compliance or advice quality.
- **Synthetic data.** Every case is synthetic.
- **Two models, one family.** qwen3.5:4b and qwen3.5:9b, Q4_K_M, thinking off. Nothing here
  generalizes to other models, quantizations or the thinking-on condition.
- **Single host, concurrency 1.** One Apple M5 Pro host with other work running; wall times and
  latencies are contended and not a performance benchmark.
- **No ranking.** No winner or ranking is implied. `uncertainty.method` is `none`: no confidence
  interval is estimated and no independence across repetitions or tasks is assumed.
- **Seeds aren't bitwise reproducibility.** Before the runs, the same seed gave byte-identical output
  for direct requests, but a CLI re-run differed in 1 of 22 responses. No reproducibility claim is
  made.
- **AML is provisional.** The as-run AML result measured a defective rubric, and the re-scored
  numbers are an offline estimate. think-off-v2 replaces both.
- **Pre-release build.** The runs used `32b7532`. Later `main` commits refactored the scenario
  executor and added the agent-workflow executor and case-level summaries. The scenario path wasn't
  re-run on the release candidate, and these packs don't exercise `agent_workflow` tasks.
- **Thinking-on not covered.** The thinking-on runs are still in progress and will be recorded
  separately.
