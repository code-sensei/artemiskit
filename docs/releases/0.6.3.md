## Scope and behavior

The native engine, CLI and SDK now support private local checkpoints, explicit safe pause and
separate-process resume. Compatible restores preserve the logical run, conversation, queued tool
calls, original deadline, tool authority, fault schedule, operation identities and cumulative usage
and budgets. Each restore has a new attempt identity; it is not a new independent repetition.

Six declared fault kinds cover unavailable tools, timeouts, stale data, incomplete data, malformed
read results and conflicting instructions in read content. Original argument and policy checks run
first. Only declared pre-effect unavailable/timeout failures can retry automatically, with at most
five total attempts per logical call and every attempt charged to the same budgets. Observation
fixtures cannot fabricate writes or change authority. Successful trace criteria count recovered
logical calls once while evidence retains failed attempts.

Checkpoint or fault/retry opt-in produces V3 public evidence with bounded digests, counts, retry
links and state-change summaries. Fresh default execution retains V2. Strict readers preserve
historical V1/V2 interpretation; adding recovery metadata to older records cannot grant retry
exceptions. Truncated public evidence cannot invent missing task proof. Private checkpoints retain
sensitive working data separately from ordinary metadata-only records.

The CLI adds `workflow resume`, `--checkpoint-dir` and `--pause-after-actions`; confirmed pause exits
10 and leaves task verification unavailable. CLI identity includes effective target/judge transport
configuration. The SDK exposes matching checkpoint options, `pauseAfterActions` and `session.pause()`;
its application supplies the configuration identity for its chosen target/client. See the
[recovery guide](../workflow-recovery.md) for runnable examples and detailed boundaries.

## Operational limits

Storage is local POSIX, same-user working data (0700 directories, 0600 files), with an exclusive
process claim and bounded checksummed atomic snapshots. A checksum is not an authenticity signature.
Copied directories are not protected by a distributed lock. Ambiguous pending operations, active
Docker crashes and terminal checkpoints refuse replay. Safe Docker pause/resume requires confirmed
cleanup before restoration. The original deadline includes time spent paused. Checkpoint files are
retained under the application's retention policy and must stay out of shared artifacts.

SDK configuration identity is a host attestation; arbitrary custom targets cannot be inspected for
hidden transport changes. Custom environments do not have checkpoint support. Power-loss/fsync
fault injection, other operating systems, distributed or external-system recovery and exactly-once
external effects remain unqualified. CI repair, optional harness integrations and professional
reports are outside this milestone; reports remain the next 0.6.4 scope.
