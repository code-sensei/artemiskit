## Result

The gate passes up to publication. The only blockers are the expected ones:

1. The manifest still carries its `draft` key, so the verifier refuses it.
2. The version bump isn't committed, so the twelve versions are not on npm.
3. The `v0.7.0` tag and the twelve package tags don't exist yet.
4. The local benchmark qualification (gate step 5) is still pending.
5. The user hasn't approved publication yet.

Two release-tooling defects were found and fixed with tests (see
[Tooling changes](#tooling-changes)).

### 4. Packed fresh consumers

## Remaining steps to publish

Run these in order on the integration checkout's `main`, on an idle machine. Steps 5, 7, 9 and 10
need explicit user approval.

1. **Qualification.** Record `docs/releases/0.7.0-local-qualification.md` and `.json` from the
   thinking-off benchmark runs. Replace every **PENDING** item in [0.7.0.md](0.7.0.md) with
   final-candidate evidence.
2. **Version commit.** On clean `main`, with every 0.7.0 change integrated and no other pending
   work, run `bun run version`. Review the twelve manifests, changelogs and `bun.lock`. Remove the
   `draft` key from `docs/releases/0.7.0.json` and finalize `0.7.0.md`, then commit, for example
   `chore(release): version the 0.7.0 experiment milestone`. The hook formats the manifests.
   Confirm `bunx changeset status` reports no pending changesets.
3. **Final local gate on that commit.** Run `bun install --frozen-lockfile`, `bun run build`,
   `bun run typecheck`, `bun run lint`, `bun test`, `bun test scripts`,
   `bun run test:migration:integrity`, `node scripts/verify-package-consumers.mjs --docker`,
   `bun scripts/verify-release.mjs local docs/releases/0.7.0.json` and
   `bun scripts/verify-release.mjs prepublish docs/releases/0.7.0.json`. Write
   `docs/releases/0.7.0-validation.json` with the Bun and Node versions for every gate. If the
   record changes after the version commit, commit it before publishing so the candidate is clean.
4. **Coordinate the publisher.** GitHub Actions is locked over billing. If it has resumed, the
   Release workflow (`changesets/action`, `bun run release`) runs on every push to `main`. Make
   sure only one publisher acts on the candidate.
5. **Publish (approval required).** With the user's npm credential in the local environment only,
   run `./scripts/publish.sh --preflight`, then `./scripts/publish.sh --publish-only` from clean
   `main`. The script now builds before checking. Its publisher re-runs `prepublish`, packs
   immutable tarballs with receipts under the Git common directory, publishes dependencies first,
   waits for registry integrity and `latest`, and then creates the twelve annotated package tags
   and `v0.7.0` locally. A pending timeout is reconciled by rerunning the same candidate, never by
   uploading again manually.
6. **Verify npm.** Run `bun scripts/verify-release.mjs registry docs/releases/0.7.0.json` and
   `node scripts/verify-package-consumers.mjs --registry --docker`.
7. **Push (approval required).** Run `git push origin main --follow-tags`, then
   `bun scripts/verify-release.mjs tags docs/releases/0.7.0.json` from the release revision.
8. **Records.** Write `docs/releases/0.7.0-publication.json` (candidate, integrities, tags) and
   the GitHub release notes. Mark 0.7.0 released in the roadmap and the 0.7.x plan.
9. **GitHub release (approval required).** Publish the release notes with the package map and
   evidence.
10. **Docs (approval required, after npm carries 0.7.0).** Update
    `docs-content/cli/commands/experiment.mdx` (workflow tasks, concurrency, per-target generation
    settings, `--timeout`, the case-level summary and `--evidence-dir`). Then push the docs
    repository and bump the submodule pointer.
