# ArtemisKit 0.5.1 release-validation record

**Release purpose:** make execution evidence reviewable by recording what model was requested and
what the target provider reported as having run, without mixing target and evaluator identities.

## Scope

- Add bounded manifest v1.3 `execution_provenance` for requested/observed target identities,
  declared generation configuration, and separately retained evaluator-model identities.
- Preserve requested/observed target identity on every case, including target errors and partial
  tool-loop failures. A CLI `--model` override is retained per case rather than only at run level.
- Validate new target and execution-provenance fields before artifact persistence, while preserving
  readability of v1.0, v1.1, and v1.2 manifests without inferred evidence.
- Ensure `artemiskit run --ci --summary json` emits parseable JSON without human progress output.

## Local-model limitations

The local checks used the OpenAI-compatible endpoint at `http://127.0.0.1:11434/v1` through the
existing OpenAI adapter. They do not establish native Ollama-adapter support. The current pricing
table can produce OpenAI-style estimates for these compatibility-path runs; those values are not
local spend and are unavailable for assurance reporting until a provider-neutral local-cost contract
is implemented.

## Release decision

This record prepares, but does not publish, the candidate. Publication requires a final clean-tree
check, package-registry preflight, release-version review, and explicit maintainer authorization.
